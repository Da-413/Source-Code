# 주식 모의투자 & AI 자동매매

주식 모의투자 플랫폼에서 여러 자동매매 전략을 실행하고, 실시간 시세를 바탕으로 매매 신호를 생성하도록 구성한 프로젝트입니다. 규칙 기반 전략뿐 아니라 논문의 **DRL-UTrans** 모델을 구현해 서비스에 연결했습니다.

> **담당:** 팀장 · AI 자동매매 모델 · FastAPI 서버 및 봇 실행 구조

## 한눈에 보기

| 항목 | 내용 |
|---|---|
| 프로젝트 | 주식 모의투자 플랫폼 |
| 자동매매 전략 | Envelope, Bollinger Band, Short-Term, DRL-UTrans |
| 핵심 구현 | 논문 모델 구현, 실시간 데이터 처리, 봇 실행 사이클, API 서빙 |
| 주요 기술 | Python, PyTorch, FastAPI, AsyncIO |

## 구현 흐름

```text
실시간 주식 데이터
        ↓
   데이터 / 지표 갱신
        ↓
자동매매 전략별 신호 판단
        ↓
   매수 · 매도 신호
        ↓
   주문 / 상태 관리
```

각 전략은 공통 실행 구조를 기반으로 시작·중지, 데이터 갱신, 실시간 가격 처리 과정을 수행하도록 구성했습니다.

## 자동매매 전략

### Envelope

Envelope 하단·중앙·상단 가격대를 이용해 매수 및 분할 매도 신호를 생성합니다. 보유 여부와 직전 주문 상태를 함께 확인해 중복 신호를 제한했습니다.

### Bollinger Band

Bollinger Band와 %B를 이용해 가격 위치를 판단하고 매수·매도 신호를 생성합니다. 밴드 내 위치와 폭을 함께 사용해 신호 강도를 계산하도록 구성했습니다.

### Short-Term

단기 가격 데이터와 기술 지표를 이용해 매매 신호를 생성하고, 분할 매수·매도와 실행 간격을 관리하도록 구현했습니다.

### DRL-UTrans

자동매매 모델을 직접 설계하는 대신 관련 논문을 읽고 구조를 분석한 뒤 DRL-UTrans 모델을 코드로 구현하고 학습했습니다. 학습된 모델의 예측 결과를 기존 자동매매 흐름에 연결해 다른 전략과 동일한 방식으로 실행할 수 있도록 구성했습니다.

## FastAPI 서빙

자동매매 로직을 웹 서비스의 백엔드와 분리하고 FastAPI 서버에서 실행했습니다.

주요 역할은 다음과 같습니다.

- 자동매매 서비스 초기화
- 전략 선택 및 실행
- 봇 상태 조회
- 봇 중지
- 외부 서비스와의 API 통신

비동기 작업은 `asyncio`를 활용해 실시간 데이터 처리와 봇 실행이 함께 동작하도록 구성했습니다.

## 실시간 데이터 처리

증권 API에서 전달되는 가격 데이터를 캐시에 갱신하고 각 전략에 전달하는 구조를 사용했습니다. 전략은 새로운 가격이 들어올 때마다 필요한 지표와 현재 포지션을 확인해 신호를 갱신합니다.

```text
증권 API
   ↓
Stock Cache
   ↓
Strategy
   ↓
Trading Signal
```

## 모델 서빙 과정에서의 개선

DRL 모델은 규칙 기반 전략보다 모델 파일과 실행 비용이 컸기 때문에 서비스에 올리는 과정에서 로딩과 메모리 사용을 함께 고려했습니다. 모델·스케일러 로딩 방식과 실행 구조를 정리해 자동매매 사이클 안에서 반복적으로 사용할 수 있도록 구성했습니다.

논문에 제시된 모델을 읽는 데서 끝내지 않고 실제 코드로 구현하고 학습한 뒤, 서비스에서 사용할 수 있는 API와 자동매매 실행 구조까지 연결했습니다. 모델 성능뿐 아니라 **학습된 모델이 서비스 안에서 어떻게 실행되어야 하는지**까지 다뤄본 프로젝트입니다.
